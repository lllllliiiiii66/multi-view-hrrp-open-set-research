- 数据 SHA-256：`9ef7fabcb0c9720cb14cd83597843184708ac6c076a8f4d13aad6044e2d0d58f`；
- 五类、两个固定视角，每视角 200 维；训练 12,015 对（每类 2,403），测试 8,010 对（每类 1,602）；
- 保留附件原 train/test，不做 PCA 或额外归一化；附件测试数据含原有噪声；
- 当前 Python AMDR：`lambda_manifold=lambda_sparse=0.01`，状态变化阈值 `3e-5`，最多 300 次，初始化种子 `20260831`；
- 训练后按原 `demo.m` 的 `1e-5` 行平方范数阈值剪枝；
- KNN 同时报告 `K=1/3/5/7/9`，不依据测试集选择 K；checkpoint 只用于恢复，不用于模型选择。

对应配置为 `configs/amdr/attachment_ship_python_reference_v1.yaml`，运行代码提交为 `7d8439cb7b89efa528a07ba927e0165ee763db25`。

## 3. 事后归因检查

在不重新训练、不修改主配置的前提下进行了三个只读检查：

1. 原始双视角直接拼接 KNN 的 Accuracy 为：K=1 99.76%、K=3 99.54%、K=5 99.35%、K=7 99.29%、K=9 99.13%；
2. 两个原始单视角各自的 1-NN Accuracy 为 99.83% 和 99.45%；
3. 用 final checkpoint 的未剪枝权重重新投影，五个 K 的准确率与剪枝后逐项完全相同。虽然 400 个输入权重行中有 160 行被阈值置零，但这些行在剪枝前已经接近零，剪枝不是失效主因。

这组证据排除了“ship 数据本身太难”“测试噪声使类别不可分”和“最终行剪枝破坏表示”三个解释。附件 ship 数据在原始空间几乎完全可分，性能断崖发生在当前 Python AMDR 表示学习之后。

## 4. 证据边界与结论

- 可以确认：当前 Python `amdr_research_v1` 即使在师兄附件的容易协议上也无法泛化，因此此前新十类 HRRP 上的低准确率不能主要归因于样本数少、601 维输入或严格奇偶角切分；当前 AMDR 实现/数值目标本身仍有根本问题。
- 不能据此确认：论文 AMDR 本身只有 22.9%。本轮没有运行原 MATLAB `train.m`，当前 Python 版本采用研究修订后的动态重加权、停止规则和数值稳定项，不能称为原代码复现。论文报告的 97.48% 仍只是论文数值，不是本项目已复现结果。
- 也不能把 99.76% 原始 KNN 当作严格研究性能：附件 train/test 共享底层 HRRP，且测试噪声由训练底层样本派生，存在已知协议泄漏。它在本轮只用于证明当前投影不应把一个容易的数据结构破坏到接近随机。

下一项最小工作不应继续扩大 fold 或数据量，而应在这套 ship 对照上定位投影失效：冻结同一数据与初始化，逐项检查目标矩阵 `T/M`、`W` 闭式方程、`D/Σ` 更新、流形矩阵尺度和每次迭代后的 train/test 几何变化。只有当前实现至少不显著劣于原始特征 KNN，才值得回到严格十类 HRRP 协议。
