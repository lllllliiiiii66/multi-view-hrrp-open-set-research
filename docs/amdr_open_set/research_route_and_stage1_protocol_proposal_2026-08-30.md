# AMDR 多视角 HRRP 开集识别：研究路线与 Stage 1 协议提案

> 日期：2026-08-30
>
> 对应阶段：P0
>
> 状态：研究主线、十类数据源、奇偶角度切分、5-fold known-only 校准、有序二视角构造和分级样本规模已经用户确认；已完成 fold 0 诊断性 smoke。
>
> 本文定义研究路线与第一阶段实验边界；smoke 只验证实现链路，不产生方法性能结论。

## 1. 收束后的问题

当前研究不再同时发明新的多视角融合框架和新的复杂拒判框架，而是回答：

> **如何在组内已有 AMDR 多视角融合框架下，实现可靠的目标身份开集识别？**

AMDR 提供闭集多视角表示与融合，开集识别是当前唯一主要改造对象。

## 2. 旧工作的继承边界

继续继承：

- 未知类完全隔离；
- 底层 HRRP 先切分、再在 split 内组多视角样本；
- known-only 阈值和模型选择；
- 统一评价器、配置、manifest、逐样本预测和结果审计。

只作参考、不默认复用：

- B0–B6 的具体模型与数值；
- MSP、OpenMax、CBD、CBD+view 等拒判机制；
- B3 特征融合诊断所得的模型特定结论。

旧开集方法中不少机制较简单，CBD 也主要建立在类别中心、方向和余弦几何上，不能仅因已有实现就视为先进或有说服力的候选。Stage 2 必须重新调研有认可度、代表性强、机制增量明确的开集方法。

## 3. 阶段链

```text
P0  严格数据协议 + AMDR 闭集复现边界
 ↓
P1  固定 AMDR + Thresholded KNN
 ↓
P2  固定 AMDR + 经重新调研确认的先进开集机制
 ↓
P3  仅在后端存在稳定上限时改造 AMDR 表示学习
```

P1 回答闭集表示天然具有多少开集能力；P2 回答不修改表示学习时，可靠的开集机制最多能做到什么程度；P3 是否必要必须由前两阶段证据决定。

## 4. P1 方法定义

保持 AMDR 的判别回归、流形约束、\(l_{2,1}\) 正则、视角权重、交替优化和投影融合完全不变。

对于测试投影 \(z\)，闭集 KNN 给出候选类别。定义：

\[
s_{\mathrm{KNN}}(z)=\frac{1}{K}\sum_{j\in\mathcal N_K(z)}\lVert z-z_j\rVert_2^2.
\]

当 \(s_{\mathrm{KNN}}(z)\leq\tau\) 时接受 KNN 预测；否则输出 `Unknown`。

第一版固定：

- 两个固定视角槽位；
- 平均平方欧氏 KNN 距离，与原 `L2_distance.m` 一致；
- 全局阈值；
- 未知分数越大越未知；
- 阈值只由已知 validation 按 95% 已知接受率确定；
- \(K\) 和任何归一化规则只由当前 fold 的已知 train/calibration 选择。

P1 不加入 EVT、原型边界、余弦边界、伪未知、额外损失或复合打分。

## 5. 已确认的数据与二视角规则

原附件组合数据不适合作为严格开集主实验，因为训练与测试组合共享底层 HRRP，且测试数据存在论文未说明的额外噪声。

已经确认：

1. 使用现有十类原始 HRRP，角度覆盖 \(0^\circ\)–\(359^\circ\)；
2. 按 15°划分为 24 个角度帧 \(F_j=\{15j,\ldots,15j+14\}\)；
3. 奇数角度进入开发/训练池，偶数角度进入最终 test 池；
4. 类别角色继续采用现有确定性 7 known / 3 unknown 划分；
5. 每条多视角样本从两个不同角度帧分别抽取一条 HRRP；
6. 不同类别统一到 601 维，复用既有固定 \(-140\,\mathrm{dB}\) 均值功率的复高斯噪声补齐配置，而不是常数零填充。
7. 180 个奇数角度确定性分成 5 fold，每份 36 个且覆盖所有 24 帧；当前 fold 每个已知类使用 144 个底层样本训练、36 个底层样本校准；
8. 没有永久 validation 集；5 个 fold 依次承担 known-only calibration，未知类不参与开发、选择或阈值确定；
9. 每个类别/split/fold 内候选为不同帧的底层 HRRP 无序对；随机抽取时优先平衡底层样本使用次数，不重复同一无序对；
10. 抽到的两条 HRRP 再以显式种子随机定向为 `view1/view2`，槽位及其帧号、角度和底层 ID 全部写入 manifest；
11. 每类每个数据角色的组合样本数依次为 smoke 100 对、pilot 500 对、首轮主实验 2000 对，全部使用显式种子。

这一采样方式的“平衡”指底层 HRRP 使用次数尽量接近，不表示枚举全部跨帧角度对。对 7 个已知类，100/500/2000 对每类分别使单次训练的 \(n\) 达到 700/3500/14000。当前实现只保存类内精确关系块，而不存储跨类的全零块，但这不代表大规模已通过。pilot 必须实测峰值内存和运行时间。把较大组合集分 mini-batch 送入现有 AMDR 闭式更新并不会自动保持原始优化目标；如后续需要在不增大单次 \(n\) 的情况下使用更多组合，必须另外定义小批优化或统计量更新，不能当作原方法的无损实现。

## 6. Stage 2 的候选筛选标准

后续文献调研不是寻找“能接上去的任意拒判器”，而是寻找：

- 在 OSR 领域具有明确认可度和代表性的机制；
- 有可靠论文、可复现实现或足够完整的算法细节；
- 能在固定 AMDR 低维投影上公平工作；
- 不依赖真实未知测试类训练或调参；
- 相比欧氏/余弦阈值具有明确的方法学增量；
- 能通过相同 projected features、相同 fold 和相同 known-only calibration 与 P1 比较。

在调研完成前不预注册具体方法，OpenMax 和 CBD 不自动进入候选清单。

## 7. 实现语言建议

主研究实现建议使用 Python，MATLAB 代码只承担参考和数值对照：

- AMDR 的核心是矩阵拼接、线性方程求解、距离矩阵、交替更新和 KNN，均可由 NumPy/SciPy 完整实现，不依赖 MATLAB 独有算法；
- Python 可以直接复用本项目已有的十类 MAT 数据读取、601 维噪声补齐、配置、manifest、评价器、测试和 Git 审计；
- 原 MATLAB 代码存在测试集调参、`D/Σ` 只初始化一次、停止规则只检查 `S{1}` 等已知问题，不适合作为新实验的主入口；
- Python 实现以论文公式和已经明确的研究协议为规范；每一处相对 MATLAB 代码的差异必须记录，不能静默修改后称为原代码复现；
- MATLAB 原文件保持只读，后续若有可用 MATLAB 环境，只在小型固定 fixture 上对照 `M`、`S`、`alpha`、`W`、平方距离和 KNN 预测。

建议形成两个明确隔离的入口：

1. `matlab_reference`：保留师兄代码事实，只用于理解和小规模数值核对；
2. `python_paper_aligned`：本项目正式、可测试、可审计的 AMDR 实现，后续 P1 在该实现上增加 Thresholded KNN。

当前工作机有可用的 Python/NumPy/SciPy 环境，但没有检测到 MATLAB 或 Octave 命令，因此现阶段也应优先推进 Python 实现；MATLAB 原样运行不作为开始 P0 数据协议工作的前置条件。

## 8. 成功标准与停止规则

P0 完成条件：

- 数据源和两视角构造规则冻结；
- 底层样本跨 split 交集为零；
- unknown 进入训练/选择/阈值的数量为零；
- AMDR 闭集入口、依赖和原附件复现边界可审计。

P1 完成条件：

- 端到端保存 AMDR 投影、KNN 预测、未知分数、阈值和逐样本结果；
- Accuracy、Macro-F1、AUROC、OSCR、FPR95、KCCR、URR 和 \(K+1\) Macro-F1 可独立重算；
- 每个 fold 和随机种子独立报告；
- 不因 test unknown 表现修改 \(K\)、阈值或分数定义。

P1 完成后先分析距离分布与失败类别，再决定是否启动 P2 调研；不直接跳到表示学习改造。
